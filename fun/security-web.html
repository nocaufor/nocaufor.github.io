Web 漏洞原理与防御

OWASP Top 10 中最高频的三种 Web 漏洞：原理、攻击示例与可落地的修复方案。

场景：Web 安全 技术栈：OWASP / Python / 前端 来源：OWASP Top 10 / OWASP 速查表 / MDN

本页面内容仅用于安全学习与合法授权测试（如 CTF、自建靶场、获得授权的渗透测试项目）。严禁用于未授权的系统入侵、数据窃取或任何违法活动。使用者须自行承担一切法律责任。

项目简介

Web 漏洞的本质是 “输入不可信”。理解 XSS、SQL 注入、CSRF 的触发条件与修复方式，是写安全代码的基本功。以下示例全部为教学简化版，请只在靶场环境中验证。

代码示例：XSS 原理与修复

html
<!-- 漏洞版：用户输入直接拼入 DOM -->
<div>你好，<span id="nick"></span></div>
<script>
  var nick = location.hash.slice(1);
  document.getElementById("nick").innerHTML = nick;  // 直接注入 -> XSS
</script>

<!-- 修复版：只当作纯文本写入 -->
<div>你好，<span id="nick-fixed"></span></div>
<script>
  var nick = decodeURIComponent(location.hash.slice(1));
  document.getElementById("nick-fixed").textContent = nick;  // 自动转义
</script>

代码示例：SQL 注入原理与修复

py
# 漏洞版：字符串拼接 SQL（输入 1' OR '1'='1 可绕过登录）
def login_bad(user: str, pwd: str):
    sql = f"SELECT * FROM users WHERE name='{user}' AND pwd='{pwd}'"
    return db.execute(sql)   # 危险！

# 修复版：参数化查询（永远不要拼接）
def login_good(user: str, pwd: str):
    sql = "SELECT * FROM users WHERE name=? AND pwd=?"
    return db.execute(sql, (user, pwd))   # 参数化，值不会被当作 SQL

代码示例：CSRF 原理与防御

py
from flask import request, session, abort

CSRF_SECRET = "change-me"

def csrf_token() -> str:
    return session.get("csrf_token") or ""

@app.before_request
def check_csrf():
    if request.method == "POST":
        token = request.form.get("_csrf")
        if token != csrf_token():
            abort(403)   # 拒绝跨站伪造请求

# 模板中写入隐藏字段：<input type="hidden" name="_csrf" value="{{ csrf_token() }}">

防御清单

  • XSS：默认用 textContent / 模板自动转义；富文本走白名单过滤。
  • SQLi：一律参数化查询；ORM 禁止 raw 拼接用户输入。
  • CSRF：POST 校验 Token、Cookie 设 SameSite=Lax/Strict。
  • 安全头：CSP、X-Frame-Options、X-Content-Type-Options 全开。

操作步骤

  1. 在 DVWA（靶场）中把安全级别调低，亲手复现三种注入，观察原理。
  2. 对照“修复版”代码改自己的项目，用 Burp Suite 复测。
  3. 接入免费扫描器（如 OWASP ZAP）做回归检查。

vuln_vs_fixed.py

SQL 注入（sqlite3 真实执行）、XSS 转义、CSRF Token 三类对照函数，可直接 python 运行看结果。

py
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""Web 三大漏洞的最小可复现对照（仅标准库，无第三方依赖）。

   1) SQL 注入：字符串拼接 SQL vs 参数化查询（sqlite3 内存库，真实跑出差异）
   2) XSS     ：直接拼 HTML        vs html.escape 转义
   3) CSRF    ：缺失校验           vs Token 常量时间比对

运行：
  python vuln_vs_fixed.py            # 打印三组对照结果
  python vuln_vs_fixed.py --selftest # 只跑断言版自测（等价 python selftest.py）

合规边界：本文件仅用于教学与自建靶场，请勿对未授权系统使用。
"""
from __future__ import annotations

import argparse
import html
import hmac
import secrets
import sqlite3

PAYLOAD_SQL = "' OR '1'='1"          # 经典 SQL 注入载荷
PAYLOAD_XSS = '<img src=x onerror=alert(1)>'


# ---------------------------------------------------------------- 1) SQL 注入
def build_db() -> sqlite3.Connection:
    """建一个内存库：users(name, pwd)，只放一个账号 admin / s3cret。"""
    conn = sqlite3.connect(":memory:")
    conn.execute("CREATE TABLE users (name TEXT, pwd TEXT)")
    conn.execute("INSERT INTO users VALUES (?, ?)", ("admin", "s3cret"))
    conn.commit()
    return conn


def login_bad(conn: sqlite3.Connection, user: str, pwd: str):
    """漏洞版：把用户输入直接拼进 SQL —— 注入载荷会改变语义。"""
    sql = "SELECT * FROM users WHERE name='%s' AND pwd='%s'" % (user, pwd)
    return conn.execute(sql).fetchall(), sql


def login_good(conn: sqlite3.Connection, user: str, pwd: str):
    """修复版：参数化查询，值永远只是值。"""
    sql = "SELECT * FROM users WHERE name=? AND pwd=?"
    return conn.execute(sql, (user, pwd)).fetchall(), sql


# -------------------------------------------------------------------- 2) XSS
def render_bad(text: str) -> str:
    """漏洞版：用户输入直接拼进 HTML。"""
    return '<div class="comment">%s</div>' % text


def render_good(text: str) -> str:
    """修复版：转义为纯文本（等价于前端 textContent 赋值）。"""
    return '<div class="comment">%s</div>' % html.escape(text, quote=True)


# ------------------------------------------------------------------- 3) CSRF
def new_csrf_token() -> str:
    """会话建立时生成，存入服务端 session（此处用返回值模拟）。"""
    return secrets.token_urlsafe(32)


def check_csrf(session_token: str, form_token: str) -> bool:
    """常量时间比对，避免时序侧信道；两者任一为空都应拒绝。"""
    if not session_token or not form_token:
        return False
    return hmac.compare_digest(session_token, form_token)


# --------------------------------------------------------------- 演示 / 自测
def demo() -> None:
    conn = build_db()
    injected, sql_bad = login_bad(conn, "admin", PAYLOAD_SQL)
    blocked, sql_good = login_good(conn, "admin", PAYLOAD_SQL)
    print("== 1) SQL 注入 ==")
    print("  漏洞版 SQL :", sql_bad)
    print("  漏洞版命中 %d 行（登录被绕过）" % len(injected))
    print("  修复版 SQL :", sql_good)
    print("  修复版命中 %d 行（登录被拒绝）" % len(blocked))

    print("== 2) XSS ==")
    print("  漏洞版输出：", render_bad(PAYLOAD_XSS))
    print("  修复版输出：", render_good(PAYLOAD_XSS))

    print("== 3) CSRF ==")
    token = new_csrf_token()
    print("  合法请求 :", check_csrf(token, token))
    print("  伪造请求 :", check_csrf(token, new_csrf_token()))


def main(argv=None) -> int:
    ap = argparse.ArgumentParser(description="Web 漏洞漏洞版 / 修复版最小对照")
    ap.add_argument("--selftest", action="store_true", help="运行断言自测（等价 python selftest.py）")
    args = ap.parse_args(argv)
    if args.selftest:
        import selftest
        return selftest.main()
    demo()
    return 0


if __name__ == "__main__":
    raise SystemExit(main())

selftest.py

unittest 断言：注入载荷命中 1 行、参数化返回 0 行、转义后无 、伪造 Token 被拒。

py
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
"""security-web 最小自测（仅标准库 unittest）：验证「漏洞能复现、修复能挡住」。

运行：
  python selftest.py
  python -m unittest selftest -v
"""
from __future__ import annotations

import unittest

from vuln_vs_fixed import (PAYLOAD_SQL, build_db, check_csrf, login_bad,
                            login_good, new_csrf_token, render_bad, render_good)


class SqlInjectionTest(unittest.TestCase):
    def setUp(self):
        self.conn = build_db()

    def test_payload_bypasses_string_concat(self):
        """拼接 SQL 会被载荷绕过（漏洞可复现）。"""
        rows, sql = login_bad(self.conn, "admin", PAYLOAD_SQL)
        self.assertIn("OR '1'='1", sql)
        self.assertEqual(len(rows), 1)

    def test_parameterized_query_blocks_payload(self):
        """参数化查询把载荷当普通字符串，登录失败。"""
        rows, _ = login_good(self.conn, "admin", PAYLOAD_SQL)
        self.assertEqual(len(rows), 0)

    def test_correct_credentials_still_pass(self):
        rows, _ = login_good(self.conn, "admin", "s3cret")
        self.assertEqual(len(rows), 1)


class XssTest(unittest.TestCase):
    def test_raw_html_is_executable(self):
        self.assertIn("<img", render_bad('<img src=x onerror=alert(1)>'))

    def test_escaped_html_is_inert(self):
        out = render_good('<img src=x onerror=alert(1)>')
        self.assertNotIn("<img", out)
        self.assertIn("&lt;img", out)


class CsrfTest(unittest.TestCase):
    def test_matching_token_passes(self):
        token = new_csrf_token()
        self.assertTrue(check_csrf(token, token))

    def test_forged_token_rejected(self):
        self.assertFalse(check_csrf(new_csrf_token(), new_csrf_token()))

    def test_empty_token_rejected(self):
        self.assertFalse(check_csrf("", new_csrf_token()))
        self.assertFalse(check_csrf(new_csrf_token(), ""))


def main() -> int:
    suite = unittest.defaultTestLoader.loadTestsFromModule(__import__(__name__))
    result = unittest.TextTestRunner(verbosity=2).run(suite)
    print("security-web selftest：%d 个用例，失败 %d" % (result.testsRun, len(result.failures) + len(result.errors)))
    return 0 if result.wasSuccessful() else 1


if __name__ == "__main__":
    raise SystemExit(main())

# Web 漏洞原理与防御 · 配套最小工程（security-web）

三个漏洞的「漏洞版 vs 修复版」对照代码 + 断言自测，用于理解 XSS / SQL 注入 / CSRF 的触发条件与修复方式。

## 运行环境与依赖清单

- Python 3.8+，**仅标准库**：sqlite3 / html / hmac / secrets / unittest / argparse

- 无必改项，开箱即可运行。

```bash
python selftest.py
```

## 对应防御清单

- XSS：输出转义（`textContent` / 模板自动转义）、富文本走白名单过滤、CSP 兜底。
- SQL 注入：一律参数化查询，禁止拼接；ORM 禁止 raw 拼接用户输入。
- CSRF：POST 校验 Token（常量时间比对）、Cookie 设 `SameSite=Lax/Strict`、关键操作二次验证。
